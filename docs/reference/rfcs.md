# RFCs

Every spec or wire-format change to Yutha goes through an RFC. The archive lives in [`/spec/rfcs/`](https://github.com/abhinavg6/yutha/tree/main/spec/rfcs) in the repo.

The RFC process itself is documented in [RFC 0001](https://github.com/abhinavg6/yutha/blob/main/spec/rfcs/0001-rfc-process.md). See also the [community RFC process page](../community/RFC_PROCESS.md) for the practical workflow.

## Browsing the archive

The full list (titles, status, dates) is maintained at [`/spec/rfcs/README.md`](https://github.com/abhinavg6/yutha/blob/main/spec/rfcs/README.md). A few of the more notable ones:

- **RFC 0001** — the RFC process itself.
- **RFC 0007** — send-path capability enforcement.
- **RFC 0009** — operator credentials and active-stream tear-down.
- **RFC 0010** — Cedar+ constitution language v1.0.
- **RFC 0011–0013** — Cedar+ extensions, evaluation model, four-stage enforcement loop.
- **RFC 0014** — Sui receipt anchoring (verifiability Layer 1).
